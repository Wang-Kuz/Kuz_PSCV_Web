# 使用与长期维护手册

## 日常操作

1. 双击根目录 `启动网页.cmd`。后台运行，不需要 npm install。
2. 在展示页切换中文/英文；向下浏览项目故事，点击详情查看媒体。
3. 打开 `http://127.0.0.1:4318/admin`，或使用页脚管理入口。
4. 左侧个人介绍修改角色、主标题和简介；页面文案可改按钮、栏目名和提示。
5. 左侧项目修改问题、解决方案、成果、角色与依据。新项目默认隐藏，填写有效 GitHub URL 后保存；核实完成再勾选展示。精选项目进入长篇故事区。
6. 分类是统计依据，可同时选 AI/Agent/企业等。交付开关仅在有依据时开启，不用于提高数字。
7. 项目底部上传视频/截图/照片，编辑中英标题。视频可播放后“添加当前播放时间为节点”，也可手填秒数与双语标题。
8. 点击右上角保存。上传完成不代表项目引用已经保存；刷新展示页确认。若提示冲突，先导出当前草稿，再刷新重新合并，不反复强制覆盖。

## 更新 GitHub 与 README

`同步GitHub.cmd`、后台同步按钮、`npm run sync:github` 使用同一逻辑。读取最新元数据并重建 README 全仓库列表，不下载源码，不自动 Git 提交。

如果需要私有仓库完整刷新，预先在你自己的终端完成 `gh auth login`，不要将 token 粘贴进本项目。断网失败保留原清单；公开 API 回退标记部分覆盖，不能宣称完成全量刷新。

新增仓库不会自动生成有夸大风险的案例。Agent 可读取当前仓库 README/关键实现，整理：承担角色、问题、技术、实现、价值、状态、证据链接；写中英文本，核实标签后录入。所有仓库仍会列于 README，包括未整理与空仓库。

## 内容与版本的关系

| 内容 | 位置 | 是否提交 Git |
| --- | --- | --- |
| 源码、默认公开文案 | frontend/、backend/、data/portfolio.seed.json | 是 |
| 仓库链接清单 | data/repositories.json 与 README | 是 |
| 本机后台编辑 | local-data/portfolio.json | 否 |
| 用户上传媒体 | local-data/uploads/ | 否 |
| 保存前 JSON 备份 | local-data/backups/ | 否 |

在后台保存不会改变 GitHub 仓库的 seed。需要把已编辑文案作为未来安装的初始内容时：导出 JSON → 逐项核对可公开内容 → 移除本机媒体引用（每项 media 改为空数组）→ revision 设为 0 → 替换 seed → 执行验证 → 查看 diff → 提交推送。原本机内容不动。这样新电脑不会拿到缺失的媒体引用，也不会把个人素材误提交。

## 备份与恢复

完整备份：停止服务，把整个 `local-data/` 复制到你认可的受控备份目录。不要把备份放在可提交路径。恢复时停止服务并先备份当前目录，再恢复完整目录后启动。

仅恢复文案：后台“备份与高级编辑”导入 JSON，检查草稿后应用并保存。保持当前 revision，让服务器检测并发冲突。若 JSON 引用了不存在的媒体，恢复相应 uploads 或移除失效引用再保存。

升级源码：先备份 local-data，再 git pull，执行测试后启动。不要删除 local-data 来解决版本问题。schemaVersion 变更必须提供显式兼容迁移与恢复说明。

## 排障

- 启动提示找不到 Node：安装 Node.js 22+，重开终端，再双击启动。
- 端口 4318 被占用：确认是否已有本项目；启动脚本仅复用正确健康标识，不应停止未知进程。命令行可设置 PORT 后 npm start；双击脚本固定 4318。
- 页面正常但修改没出现：后台是否点击保存、展示页是否刷新、是否存在 runtime 覆盖 seed，逐一检查。
- 视频不能播放：用浏览器兼容编码重新导出 MP4/WebM；文件扩展名不是编码证明。
- 保存 409：另一个窗口已修改数据。导出草稿，再刷新、合并，不删 revision 检查。
- 同步失败：检查 gh 登录和网络；不关闭代理或修改系统网络配置。不会因失败清空现有项目。
- 查看 `local-data/server.stderr.log` / stdout；它们不进入 Git，分享前脱敏。

## Agent 更新步骤

读根控制文档 → 检查 git status 与本地覆盖 → 明确修改范围 → 备份用户数据 → 修改 → `npm test` / `npm run check` → 浏览器检查受影响交互 → 更新 STATUS/日志 → 检查暂存文件 → 提交推送 → 核对远端 SHA。不能把 HTTP 200 解释为视觉或业务验收。
