# 宣传手册与工程介绍导出

## 交付文件与范围

- `output/pdf/` 保存中文首页宣传手册 PDF，保留全首页章节、六个重点故事和全部项目索引；动画以静态画面呈现，GitHub 链接可点击。
- `output/docx/` 保存工程项目介绍 Word；每个可见项目独占一页，四个字段为工程名称、工程技术栈、工程简单描述、解决的痛点，项目之间使用显式换页符。
- 当前完整范围是 46 个仓库，一仓库一条目。学习骨架、数据资料及原型也保留，技术与状态按证据填写；46 不表示全部生产交付。
- PDF 文件名保留所有者命名。对外发送之前重新核对网站、Word 和仓库清单的集合相等。

## 更新流程

1. 先运行 `npm run sync:github`，核对新增仓库，按 CONTENT-EVIDENCE 规则补齐双语条目。元数据 size 可能滞后，不能当作空仓库的最终判断。
2. 检查是否存在 `local-data/portfolio.json`。导出脚本和网站都会优先使用本机内容；不能删除该文件来强制使用种子。用户内容合并使用 revision API，保留媒体与未知字段。
3. 使用含 python-docx 的 Python 运行 `scripts/export/build-docx.py`。它按当前可见条目动态生成正文、页码总数及换页符；不硬编码 46。
4. 用 LibreOffice 渲染 DOCX 为内部校对 PDF/PNG。检查页数等于可见项目数，换页符为项目数减一，每页四字段、对应项目和正文完整。逐页检查长标题、技术栈与 URL，不靠 XML 检查代替视觉核验。
5. 启动网站，打开全新中文首页，重置筛选为全部。以 1440×960 视口启用减少动态效果；通过本地浏览器开发工具执行 `scripts/export/prepare-brochure.js`。该脚本只改当前导出标签页 DOM，关闭即可恢复；不要保存回首页源码。
6. 浏览器打印为 PDF，开启背景，采用 CSS 页面尺寸 15×10 英寸、零边距，关闭浏览器默认页眉页脚。页数应为 7 + 重点故事数 + ceil(项目数 / 6)，当前为 21 页。运行 `scripts/export/verify-exports.py --rendered-docx <Word渲染PDF路径> --bookmark`，核对全部项目名、摘要、GitHub 链接以及 Word 换页与正文，补充章节书签后再逐页渲染检查。
7. 运行 `npm test`、`npm run check`、`git diff --check`。默认种子检查会拒绝缺失、重复或隐藏的仓库条目；后台仍允许用户自行隐藏项目，导出时应明确范围差异。
8. 更新状态及验证记录，把最终 PDF、DOCX、生成脚本和维护文档纳入 Git；临时截图、渲染器、日志、用户上传内容与邮件回执留在忽略目录。邮件发送必须有用户授权，并核对已发送附件名称、数量与大小。

## 运行依赖

网站仍为 Node.js 22+ 零运行依赖。离线文档生成另外需要 python-docx；视觉检查需要 LibreOffice、Poppler 和 pypdf。Codex 环境优先通过 load_workspace_dependencies 获取绑定的 Python/Node 与库路径，不把本机绝对运行时路径硬编码进工程。普通维护者可使用自己的等价工具环境。
